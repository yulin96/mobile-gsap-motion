# 场景验收

用于维护 skill 时检查指令是否导向合适的决策。下表是验收标准，不是已运行的页面测试；实际验证依据当前项目约定执行。

| 用户请求 / 工程条件 | 预期行为 | 需要识别的偏差 |
| --- | --- | --- |
| “优化整体动画，部分元素有创意一点”；已有默认路由动画 | 沿用路由效果，优化页面内部层次，按素材挑选少量细节 | 擅自加入全局缩放或共享元素转场 |
| “添加 H5 入场动画”；项目没有路由动画 | 按内容安排入场，保留当前导航方式 | 把缺少转场视为必须新增转场 |
| “这个返回要缩回菜单卡片，里面的元素依次消失” | 读取现有返回 hook、CSS 和缓存逻辑，为指定返回路径适配，统一完成信号并处理取消 | 改成所有页面统一缩回；路由层和内容层抢同一变换 |
| “滚动然后出现动画可以先去掉，默认可以连续都展示了” | 移除相关滚动门槛，将内容和地图内部层次接进入场 timeline | 保留 observer 门槛；直接删除全部动画 |
| “逐行随滚动出现，快速滚动也不能插队” | 观察稳定外层与真实滚动容器，统一队列，补齐跳过的行，参数联动 | 每批 stagger 从零开始；误用连续入场替代明确要求 |
| “动画幅度大点”；随后说“太慢了，再快点” | 最新指示优先，按当前页面调整幅度和节奏，检查累计等待及裁切 | 固定沿用历史项目的秒数或曲线 |
| “只分析闪烁，不改代码” | 定位初始 CSS、from/fromTo、clearProps、生命周期和转场交接，给出证据 | 顺手修代码；静态检查后声称播放正常 |
| “用新导出的标题图做逐行动画” | 核对新图尺寸、行范围和间距，按实际素材裁切 | 直接搬用旧图坐标或把图片当可拆分 DOM 文字 |

复查新指令是否与现有章节、参考代码或默认调用提示冲突。代码格式与静态检查通过，只证明对应检查通过；首帧、衔接和缓存返回仍需浏览器观察，真实触摸与设备性能仍需相应设备验证。
